1. Увеличение времени отклика ins-product-aggregator
Сейчас сервис делает синхронные запросы ко всем страховым компаниям при каждом вызове.
При добавлении ещё 5 компаний время ответа увеличится (так как запросов станет больше).
Возможны таймауты и ошибки при взаимодействии с API страховых компаний.

2. Ненадёжность обновления тарифов в core-app и ins-comp-settlement
Core-app обновляет данные раз в 15 минут → потенциально показывает устаревшие тарифы.
Ins-comp-settlement обновляет данные раз в сутки → может работать с неактуальными тарифами.
REST-запросы могут не сработать (проблемы сети, таймауты).

3. Высокая зависимость ins-comp-settlement от core-app
Ins-comp-settlement раз в сутки запрашивает core-app для получения оформленных страховок.
Если core-app недоступен в этот момент, ins-comp-settlement не сможет обработать данные.
Возможно дублирование запросов в случае сбоя.

4. Отсутствие событийной модели
Все взаимодействия строятся на опросе (polling), что создаёт нагрузку и даёт задержки.
Вместо polling лучше использовать Event-Driven подход с Kafka / RabbitMQ.

5. Рост нагрузки на ins-product-aggregator
Сейчас core-app и ins-comp-settlement дергают API каждые 15 минут и раз в сутки.
При добавлении новых компаний это увеличит количество запросов, что замедлит работу.
